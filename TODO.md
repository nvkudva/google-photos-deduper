Less pressing than written: the range filter plus the bisection seek already let a stopped run continue by setting the range to end where it stopped, at a cost of ~12 probes rather than a full re-walk. - [x] Add LSH banding to src/grouping.js so near-duplicate matching works across capture dates. Today only the exact-hash pass is global; the Hamming pass is bucketed by UTC day, so the same photo re-uploaded without EXIF (different capture date) is only caught if its 64-bit dHash matches byte-for-byte. Split each hash into four 16-bit bands, bucket on each band, compare within bands.

- [x] Guard against union-find chaining in src/grouping.js: members are merged transitively, so A~B and B~C puts A and C in one group even when A and C are 10 bits apart. The flat-crop fix removed the worst case, but a long chain of gradual near-matches can still over-merge. - [ ] Background deletion in a second window: both mechanics work, but it steals focus. Spike measured via chrome.windows.create({focused:false}): the unfocused window reported visibilityState "visible" with 16 tiles rendered, so Google Photos does keep rendering there, and a CDP Input.dispatchMouseEvent landed in it as a trusted event (click counter 0 to 1, isTrusted true). The problem is what followed - after that single click the user's own window reported document.hasFocus() false. Input.dispatchMouseEvent activates the window it is sent to, so a run would yank focus roughly once a second for the length of the run, which defeats the point of it being in the background. Worth one more look at whether the activation can be avoided; if not, this approach is dead and foreground deletion at ~1.24s a photo stands.

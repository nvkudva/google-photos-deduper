- [x] Add LSH banding to src/grouping.js so near-duplicate matching works across capture dates. Today only the exact-hash pass is global; the Hamming pass is bucketed by UTC day, so the same photo re-uploaded without EXIF (different capture date) is only caught if its 64-bit dHash matches byte-for-byte. Split each hash into four 16-bit bands, bucket on each band, compare within bands.
- [x] Measure actual scan throughput. Instrumented in src/scanner.js and stored on the lastScan meta row: 29.95 photos/sec, 18.2 photos per scroll step, split 58% screen capture and 42% waiting for thumbnails to paint. The two together account for 99.7% of wall clock, so any further speedup has to come out of one of them.
- [x] Check memory at 200k. Measured at 5,101 rows and scaled: 309 bytes per row (59MB at 200k), getAll() 25ms (~1s at 200k), the known-id Set 24MB against a 4GB heap limit. Not a bottleneck; no streaming needed.
- [x] Reduce delete wall-clock. Measured, and the cost is not where the note assumed. A deletion itself takes ~3s once the photo is on screen (2 deleted at 18s and 21s). The cost is finding targets: the deleter walks from the top at 1,100px per 500ms over a 2.5M-pixel scroller, so a full pass is ~19 minutes regardless of how many photos are being deleted - 166s of a real run covered 334k of 2.58M pixels and found 2 of 62. Fix by seeking to each target's capture date the way src/scanner.js already bisects, instead of scrolling past the whole library.
- [x] Handle the tab-visibility constraint over multi-hour runs. Moot: the RPC scanner never renders the grid. - [x] Guard against union-find chaining in src/grouping.js: members are merged transitively, so A~B and B~C puts A and C in one group even when A and C are 10 bits apart. The flat-crop fix removed the worst case, but a long chain of gradual near-matches can still over-merge. Consider capping group diameter, or splitting a group when its max pairwise distance exceeds ~2x the threshold.
